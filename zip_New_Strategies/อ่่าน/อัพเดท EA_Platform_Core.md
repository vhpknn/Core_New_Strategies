ข้อความนี้ของ Claude อธิบายวิธี "อัปเกรดเครื่องยนต์ (Core)" ให้กับบอทตัวเก่าของคุณครับ
จุดเด่นของระบบนี้คือ มันจะสร้างโฟลเดอร์เวอร์ชันใหม่ (เช่น v1.2) แยกออกมาต่างหาก โดยไม่ลบของเก่า (v1.1) ทำให้ถ้าอัปเกรดแล้วบอทพัง คุณสามารถสลับกลับไปใช้ตัวเดิมได้ทันที
สรุปขั้นตอนการทำงานแบบเข้าใจง่ายๆ มี 4 ขั้นตอนหลัก ดังนี้ครับ:

ขั้นที่ 1: เตรียมไฟล์ Core รุ่นใหม่ให้พร้อม

ไปที่โฟลเดอร์ต้นฉบับของ Core หลัก (EA_Platform_Core ในเครื่องคุณ) แล้วอัปเดตหรือสลับเวอร์ชัน (Checkout tag) ให้เป็นรุ่นใหม่ที่ต้องการ (เช่น v1.2)

ขั้นที่ 2: สั่งเครื่องมือคัดลอกเวอร์ชันใหม่มาใส่บอท

เปิด Terminal ในโฟลเดอร์บอทของคุณ (เช่น EA_SMC) แล้วรันคำสั่ง:
cmd
tools\update_core.bat --platform <ที่อยู่โฟลเดอร์ EA_Platform_Core> --version v1.2
Use code with caution.
• ระบบจะทำอะไรให้?
	1. เทียบโค้ดเก่ากับใหม่ และแจ้งระดับความเสี่ยงให้ดูก่อน (ต่ำ / ปานกลาง / สูง) แล้วถาม Y/N เพื่อยืนยัน
	2. เมื่อตอบ Y ระบบจะสร้างโฟลเดอร์ Strategies\SMC\v1.2\ ขึ้นมาคู่กับ v1.1 ของเดิม โดยยกโค้ดกลยุทธ์ของคุณมาใส่คู่กับ Core ตัวใหม่ให้พร้อมสรรพ
	3. สร้างไฟล์เช็กลิสต์ชื่อ docs/work/CORE_UPDATE_v1.1_to_v1.2.md ไว้ให้คุณตรวจงาน

ขั้นที่ 3: ให้ AI ช่วยเช็กว่าโค้ดบอทต้องแก้ตรงไหนบ้าง

บางครั้ง Core รุ่นใหม่มีการเปลี่ยนชื่อคำสั่ง ทำให้โค้ดบอทเดิมของคุณอาจทำงานไม่เข้ากัน จึงต้องให้ AI ช่วยตรวจ:
1. รันคำสั่งรวบรวมไฟล์สำหรับงานอัปเดต:cmd
python tools\make_ai_bundle.py --job coreupdate
Use code with caution.
2. ส่งชุดไฟล์ที่ได้ให้ AI พร้อมข้อความคำสั่ง ข้อ 3 ใน docs/AI_START_PROMPT.md
3. AI จะวิเคราะห์และแจ้งว่าต้องแก้โค้ดกลยุทธ์ตรงไหนบ้าง เพื่อให้ใช้งานกับ Core รุ่นใหม่ได้

ขั้นที่ 4: คอมไพล์ ทดสอบ และปิดงาน

1. แก้โค้ดตามที่ AI แนะนำ (ถ้ามี)
2. เปิดไฟล์ EA ในโฟลเดอร์ใหม่ (Strategies\SMC\v1.2\SMC_EA_TH.mq5) กด Compile (F7) เช็กว่าผ่าน 0 errors 0 warnings
3. รัน run_checks.bat เพื่อตรวจสอบความถูกต้องของเอกสาร
4. นำไปทดสอบบนบัญชี Demo จนมั่นใจว่าทำงานปกติ ค่อยสั่ง git commit และติด tag เวอร์ชันใหม่

ข้อห้ามเด็ดขาด 2 ข้อ (กันระบบรวน)

• ห้ามใช้คำสั่ง sync_core เพื่ออัปเดตเวอร์ชัน: sync_core มีไว้ซ่อมไฟล์ในเวอร์ชันเดิมเท่านั้น ถ้าจะข้ามเวอร์ชันต้องใช้ update_core เสมอ
• ห้ามเข้าไปแก้ไฟล์ข้างในโฟลเดอร์ Core/ เอง: หากแก้เอง ระบบตรวจสอบ (verify_core) จะฟ้อง Error ทันที
หากต้องการให้ช่วย เตรียมคำสั่ง update_core.bat แบบระบุ Path เต็ม (โดยบอกที่อยู่โฟลเดอร์ EA_Platform_Core ในเครื่องของคุณ) หรือมีข้อสงสัยตรงขั้นตอนไหน แจ้งได้เลยครับ

ข้อความนี้ของ Claude อธิบาย "ระบบส่งไม้ต่อ (Handoff)" ครับ หัวใจสำคัญคือ AI ตัวใหม่ไม่ต้องฟังคำอธิบายจากคุณ แต่จะไปอ่านความจำทั้งหมดจากไฟล์เอกสารใน GitHub
ดังนั้น ทุกครั้งที่ทำงานเสร็จและกำลังจะเปลี่ยนแชตหรือเปลี่ยน AI ตัวใหม่ คุณต้องทำ 2 ช่วง คือ ปิดงานแชตเก่า และ เปิดงานแชตใหม่ ตามขั้นตอนง่ายๆ ดังนี้ครับ:

ช่วงที่ 1: ปิดงานในแชตเก่า (อัปเดตสมุดบันทึก)

ก่อนปิดหน้าต่างแชตที่กำลังคุยอยู่ ต้องให้ AI ตัวเดิมจดบันทึกสถานะล่าสุดลงในไฟล์เอกสารของโปรเจกต์ (CURRENT_STATE_Core.md) ก่อน
1. สั่งให้ AI สรุปและอัปเดตไฟล์สถานะ: ก๊อปปี้ข้อความนี้ไปวางในแชตเดิม:ปิดงานรอบนี้ ร่างแพตช์อัปเดต docs/work/CURRENT_STATE_Core.md, docs/handoff/PROJECT_HANDOFF_v5.md และ DECISIONS_INDEX.md (ถ้ามีมติใหม่) ให้ระบุ: ทำอะไรเสร็จแล้ว, Commit ฐาน, ไฟล์ที่แก้, ผลทดสอบที่มีหลักฐาน, สิ่งที่ยังไม่ได้ทดสอบ, งานค้างและลำดับถัดไป, สิ่งที่ห้ามทำ
2. นำแพตช์มาใส่ในไฟล์ + ตรวจสอบ: เอาข้อความที่ AI ร่างให้มาแปะทับในไฟล์ดังกล่าว แล้วรัน tools\run_checks.bat (ต้องขึ้น ERROR 0)
3. อัปโหลดขึ้น GitHub (git push): สำคัญมาก! AI ตัวใหม่จะมองเห็นเฉพาะงานที่ขึ้นไปอยู่บน GitHub แล้วเท่านั้น ถ้าแก้ในเครื่องอย่างเดียวแล้วลืม Push AI ตัวใหม่จะไม่เห็นความคืบหน้าล่าสุด

ช่วงที่ 2: เปิดแชตใหม่กับ AI ตัวอื่น (เริ่มงานทันที)

เมื่อเปิดแชตใหม่ (ไม่ว่าจะเป็น Claude, ChatGPT หรือ Gemini) ให้ทำตามนี้ครับ:

	• แนบไฟล์ Jigsaw-Patch-Rule.txt เข้าไปในแชตด้วย (เพื่อให้ AI เขียนแพตช์แก้โค้ดได้ถูกฟอร์แมต)

ใช้เครื่องมือ `update_core` ซึ่งสร้างโฟลเดอร์ Core รุ่นใหม่ข้างของเดิม โดยไม่แตะรุ่นเก่า คุณจึงย้อนกลับได้ตลอด ขั้นตอนทั้งหมดอยู่ใน `tools/README_tools.md` ของ repo

## ลำดับการทำ

1. **เตรียม platform:** clone `EA_Platform_Core` ไว้ในเครื่อง แล้ว checkout ตาม tag ของ Core รุ่นที่ต้องการ ถ้า platform ไม่ตรง tag หรือมีไฟล์ค้าง เครื่องมือจะเตือนแต่ไม่หยุด จึงควรตรวจเองก่อน
2. **รัน update_core:**
   ```text
   tools\update_core.bat --platform <โฟลเดอร์ EA_Platform_Core> --version v1.2
   ```
   ตัวอย่างนี้ใช้ v1.2 เป็นเลขสมมติ ถ้าไม่ใส่ `--apply` จะแสดงแผนแล้วถาม Y/N ก่อนเขียนไฟล์ ถ้ามีหลายกลยุทธ์ให้เพิ่ม `--strategy <ชื่อ>` และเพิ่ม `--from-version v1.1` เมื่อต้องการระบุรุ่นเดิมเอง
3. **อ่านแผนและระดับความเสี่ยง:** เครื่องมือเทียบ Core เดิมกับใหม่ (ไฟล์ที่เพิ่ม ลบ แก้) และเทียบ `Core_StrategyAPI.mqh` แล้วประเมินความเสี่ยงให้ ระดับสูงคือ API เปลี่ยนหรือมีไฟล์ถูกลบ ปานกลางคือมีไฟล์หรือ Input เพิ่ม ต่ำคือแก้ภายใน และเป็นเพียงการประมาณ ไม่ใช่การพิสูจน์
4. **ดูสิ่งที่ถูกสร้าง:**
   - `Core/<รุ่นใหม่>/` พร้อม `PINNED_FROM.txt`
   - `Strategies/<ชื่อ>/<รุ่นใหม่>/` คัดลอกจากรุ่นเดิม เปลี่ยนสำเนา Core และเขียน `CORE_MANIFEST.txt`
   - `docs/work/CORE_UPDATE_<เดิม>_to_<ใหม่>.md` เป็นรายการตรวจให้ติ๊กทีละข้อ
5. **ให้ AI ประเมินผลกระทบ:** รัน `python tools\make_ai_bundle.py --job coreupdate` ถ้า AI เข้า GitHub ไม่ได้ (ชุดนี้รวม CORE_UPDATE ล่าสุด, `Core_StrategyAPI` ทุกรุ่น และโค้ดกลยุทธ์) แล้ววางข้อความข้อ 3 ใน `docs/AI_START_PROMPT.md` AI ต้องส่งแผนแก้ก่อนและรอคำว่า "เริ่มงาน" ถ้าต้องแก้ Core เอง AI ต้องหยุดและแจ้งว่าเป็นงานของ `EA_Platform_Core`
6. **ทำตามรายการตรวจ:** คอมไพล์ EA ทั้ง 3 ตัว (0 errors 0 warnings), `run_checks.bat`, ทดสอบ, `log_entry`, commit แล้วติด tag เอง เครื่องมือไม่ commit และไม่ติด tag ให้

## ข้อควรระวัง

- โฟลเดอร์กลยุทธ์ต้องใช้เลขรุ่นเดียวกับ `Core/vX` ที่ปักไว้ ไม่เช่นนั้น `verify_core` จะฟ้อง `ไม่พบ Core/vX/include ที่เป็นรุ่นเดียวกับสำเนา`
- ห้ามใช้ `sync_core` กับ Core รุ่นใหม่ ตัวนี้มีไว้ซ่อมสำเนาที่ไม่ตรงต้นฉบับของรุ่นเดิมเท่านั้น
- ห้ามแก้ไฟล์ในสำเนา Core เอง ถ้าแก้ `verify_core` จะขึ้น `ถูกแก้หลัง sync (ไม่ตรง manifest)`
- ถ้าคอมไพล์ผ่านแต่ฟีเจอร์ใหม่ไม่ขึ้น แปลว่าคุณคอมไพล์ก่อนปรับสำเนา Core ให้คอมไพล์ใหม่
- `update_core` ไม่เขียนทับโฟลเดอร์ที่มีอยู่แล้ว และไม่แตะรุ่นเดิม ถ้าผลทดสอบไม่ผ่าน ให้กลับไปใช้รุ่นเดิมต่อได้ทันที

## ตัวอย่าง

สมมติ Core ออก v1.2 และเพิ่มฟีเจอร์ Session Close (ฟีเจอร์นี้เป็นสมมติ) คุณ checkout `EA_Platform_Core` ที่ tag `v1.2` แล้วรัน `update_core` เครื่องมือน่าจะประเมินความเสี่ยงระดับปานกลาง เพราะมี Input เพิ่ม และสร้าง `Strategies/SMC/v1.2` ข้าง `v1.1` จากนั้นใช้ AI ตรวจว่ากลยุทธ์ต้องแก้อะไรเพื่อใช้ฟีเจอร์ใหม่ ซึ่งต้องทำเป็นชุดแพตช์ปกติ และทดสอบ Demo ก่อนเลิกใช้ v1.1

2. ใส่แพตช์ในไฟล์เอง รัน `tools\run_checks.bat` ให้ check_docs ERROR 0 (เครื่องมือเตือนถ้า CURRENT_STATE ตามหลัง HEAD เกิน 3 commit)
3. commit และ **push** ตามกติกา ข้อ 6 ของ `AI_READ_SCOPE.md` ระบุว่า Repo ที่ AI อ่านได้คือสิ่งที่ push แล้ว ถ้าไม่ push AI ตัวใหม่จะไม่เห็นงาน และ AI ไม่ commit หรือติด tag ให้ (ข้อ 7)
4. ถ้า Core ออกรุ่นใหม่แล้ว ให้ติด tag ตามกติกา เพื่อให้ `update_core` ของกลยุทธ์ checkout ได้ตรงรุ่น

## เริ่มแชตใหม่กับ AI ตัวอื่น

วางข้อความนี้ (เปลี่ยนรุ่นให้ตรง) จาก `AI_READ_SCOPE.md` หัวข้อ 2:

```text
อ่าน docs/AI_READ_SCOPE.md ก่อน แล้วทำ "งาน Core" รุ่น v1.1 อ่านเฉพาะไฟล์ในรายการงาน Core ห้ามเปิดไฟล์ของ Hedge หรือ Pending ถ้าจำเป็นให้บอกเหตุผลและขออนุญาตก่อน ก่อนตอบสรุปให้แจ้งรายชื่อไฟล์ที่คุณเปิดอ่านจริงทั้งหมด
```

- ถ้า AI เข้า GitHub ไม่ได้: `python tools\make_ai_bundle.py --job core --version v1.1` แล้วแนบ 3 ไฟล์เหมือนเดิม
- ส่ง `Jigsaw-Patch-Rule.txt` ให้ในแชตด้วย เพราะไฟล์นี้ไม่ได้อยู่ใน Repo (ข้อ 8)
- AI ตัวใหม่จะอ่านสถานะ แล้ว**ตรวจกับ Repo** (Commit ล่าสุด และไฟล์ที่ระบุว่าแก้แล้วมีอยู่จริง) แล้วแจ้งถ้าไม่ตรง (ข้อ 11) ถ้าคุณแก้ในเครื่องโดยยังไม่ push ให้ส่งเนื้อไฟล์นั้นให้ AI เอง
- ถามในแชตแรกว่า "เปิดอ่านไฟล์ไหนไปบ้าง" เทียบกับหมวดงาน Core หากเปิดไฟล์ในหมวดห้ามอ่านหรือของงานอื่น ให้เตือนและสั่งทิ้งสิ่งที่ได้จากไฟล์นั้น

## ส่งต่อไปยังกลยุทธ์ที่ใช้ Core นั้น

การอัปเดต Core ที่ต้นฉบับไม่ได้เปลี่ยนกลยุทธ์โดยอัตโนมัติ ต้องทำต่อใน repo ของแต่ละกลยุทธ์ ด้วย `update_core` แล้วใช้ข้อความ "งาน C" ของแม่แบบ ซึ่งอ่าน `docs/work/CORE_UPDATE_*.md` ที่เครื่องมือสร้างให้ ไฟล์นี้ทำหน้าที่ส่งต่อให้ AI ตัวใหม่ในฝั่งกลยุทธ์ ใส่สถานะลง `docs/work/CURRENT_STATE.md` ของกลยุทธ์นั้นเมื่อจบแต่ละชุดงาน

## ข้อควรระวัง

- **ห้าม AI แก้สำเนา Core:** ถ้ากลยุทธ์ต้องการความสามารถที่สำเนา Core ไม่มี ให้หยุดและเปิดเป็นงาน Core ในแชตแยก (ข้อ 1 ถึง 10)
- **ขอบเขตของ AI แต่ละงาน:** ถ้าเพิ่มกลยุทธ์ใหม่ใน platform ต้องเพิ่มหัวข้อ "งาน <ชื่อ>" ใน `AI_READ_SCOPE.md`, เพิ่ม `--job` ใน `make_ai_bundle.py` และปรับเงื่อนไขใน `check_docs.py` (หัวข้อ 11 ของไฟล์นั้น)
- **เอกสารที่ล้าสมัย:** ย้ายเข้าตาราง "ห้ามอ่าน" ติดป้าย ARCHIVED ไม่เช่นนั้น AI ตัวใหม่อาจอ่านสถานะเก่าแล้วเข้าใจผิด

ถ้าต้องการ ผมร่างแพตช์ปิดงานสำหรับ `CURRENT_STATE_Core.md` ให้ได้ แต่ต้องการเนื้อไฟล์ปัจจุบัน และสถานะงานรอบที่เพิ่งทำเสร็จจากคุณก่อนครับ
