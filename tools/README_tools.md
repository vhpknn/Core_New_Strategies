# README — tools ของ EA Platform Core (อธิบายแบบเข้าใจง่าย)

อัปเดต 17 พ.ย. 2026 | ที่อยู่: `tools\` ทุกตัวเป็นไฟล์ `.bat` (ดับเบิลคลิกได้) ที่เรียกสคริปต์ Python 3 ในโฟลเดอร์เดียวกัน
ต้องติดตั้ง Python 3 ก่อน (ถ้าไม่มี จะขึ้น `[ERROR] ไม่พบ Python`) ทุกตัวใช้ไลบรารีมาตรฐานของ Python เท่านั้น ไม่ต้องติดตั้งเพิ่ม (ยกเว้น Collector ที่มีตัวเลือกเสริม)

## 1. ภาพรวม: ใช้ตัวไหนตอนไหน
| เครื่องมือ | เปรียบเทียบง่ายๆ | ใช้ตอนไหน |
|---|---|---|
| `sync_core.bat` | เครื่องถ่ายเอกสาร: ถ่าย Core ต้นฉบับไปให้ EA ใช้ | **ทุกครั้งที่แก้ไฟล์ใน Core** |
| `verify_core.bat` | ผู้ตรวจสอบ: เช็กว่าทุกอย่างตรงกติกา | หลัง sync + คอมไพล์ทุกครั้ง และก่อน Commit |
| `next_magic.bat` | ใบเบอร์คิว: บอกเลข Magic ถัดไปที่ยังว่าง | หลังเพิ่ม Preset (.set) ใหม่ หรือเมื่อ verify เตือนว่า MAGIC_NEXT ล้าสมัย |
| `convert_sets.bat` | เครื่องแปลง: แปลง .set ของโปรเจกต์เก่าเป็นของ Core ใหม่ | ครั้งเดียวตอนนำ Preset จากโปรเจกต์เก่าเข้ามา |
| `compare_ref.bat` | เทียบฟังก์ชันของเก่ากับของใหม่ทีละตัว | ตอนตรวจว่า Core ใหม่ไม่เปลี่ยนพฤติกรรมจากต้นฉบับ (ข้อ C-09) |
| `Collector_Tools\bots\Hedge1\run.bat` | เครื่องอัดเทป: เก็บ Log ของ EA แยกตาม Preset | ตอนทดสอบด้วย Demo ทุกชุดที่ต้องส่งหลักฐาน |
| `make_ai_bundle.bat` | แพ็กกระเป๋าส่งต่องาน: รวมเอกสารและโค้ดอ้างอิงให้ AI | ก่อนเริ่มแชตกับ AI ที่เข้า GitHub ไม่ได้ |
| `run_checks.bat` | ใบรายงานผลตรวจสุขภาพ: รันเครื่องมือตรวจทั้งหมดรวมเป็นไฟล์เดียว | ทุกครั้งที่วางไฟล์ที่ AI ส่ง ก่อนส่งผลกลับ |
| `log_entry.bat` | สมุดจดอัตโนมัติ: เติมเวลา เลขรายการ ไฟล์ที่แก้ ผลตรวจ ให้รายการใน LOG | ทุกครั้งที่จบชุดงาน ก่อนต่อท้าย LOG |
| `Strategies\TradeDesk\tools\mock_edition_server.bat` | เซิร์ฟเวอร์จำลองตรวจสิทธิ์ (เฉพาะ TradeDesk อยู่ในโฟลเดอร์ของกลยุทธ์ตาม D-29) | ตอนทดสอบไคลเอนต์ตรวจสิทธิ์ของ TradeDesk ดูหัวข้อ 8.2 |
| `_common.py` | กล่องเครื่องมือกลาง (ไม่ได้รันเอง) | ไม่ต้องแตะ |

## 2. ลำดับประจำวัน (จำ 4 ข้อนี้ก็พอ)
**แก้ไฟล์ใน Core:** บันทึกไฟล์ → `sync_core.bat` → คอมไพล์ EA ทุกตัว → `verify_core.bat`
อย่าคอมไพล์ก่อน sync เพราะ EA อ่านสำเนา Core ในโฟลเดอร์กลยุทธ์ ถ้ายังไม่ sync จะได้โค้ดเก่า (เจอมาแล้ว: ภาษา Inputs ไม่สลับ)
**เพิ่ม Preset (.set) ใหม่:** ลงทะเบียน Magic ใน `docs\decisions\MAGIC_REGISTRY.md` → สร้างไฟล์ .set → `next_magic.bat --apply` → คอมไพล์ EA → `verify_core.bat`
**ก่อน Commit:** `verify_core.bat` ต้องได้ `ERROR 0 | WARN 0`

## 3. sync_core — คัดลอก Core ต้นฉบับไปให้ EA
**คืออะไร:** Core ต้นฉบับอยู่ที่ `Core\v1.0.0\include\` แต่ EA ของแต่ละกลยุทธ์ใช้ "สำเนา" ที่ `Strategies\<ชื่อ>\v1.0.0\Core\include\` เครื่องมือนี้เทียบและคัดลอกต้นฉบับทับสำเนา **ห้ามแก้ไฟล์ในสำเนาเอง** แก้ที่ต้นฉบับเท่านั้น
**วิธีใช้:**
1. ดับเบิลคลิก `tools\sync_core.bat`
2. อ่านตาราง: `SAME` = ตรงกัน, `DIFF` = ต่างกัน, `MISSING` = สำเนายังไม่มีไฟล์นี้, `EXTRA` = สำเนามีไฟล์เกิน (เตือนอย่างเดียว ไม่ลบให้)
3. ถ้ามี DIFF หรือ MISSING จะถามว่าจะคัดลอกทับไหม กด `Y` เพื่อคัดลอก กด `N` เพื่อยกเลิก
4. เสร็จแล้วต้องคอมไพล์ EA ใหม่
**สิ่งที่ทำให้อัตโนมัติ:** สำรองไฟล์เดิมที่ถูกทับไว้ที่ `Strategies\<ชื่อ>\v1.0.0\Core\Core_backup\<วันที่_เวลา>\` และเขียน `CORE_MANIFEST.txt` (รายการไฟล์ + ค่า SHA-256) เพื่อให้ `verify_core` จับได้ถ้ามีใครแก้สำเนา
**ตัวเลือก (พิมพ์ใน cmd):** `sync_core.py --apply` คัดลอกจริง | `--yes` ไม่ถามยืนยัน | `--src <โฟลเดอร์>` เลือกต้นฉบับ | `--target <โฟลเดอร์>` เลือกสำเนาเฉพาะกลยุทธ์
**หลายรุ่นของ Core (D-28.1):** สำเนาแต่ละตัวใช้ต้นฉบับรุ่นเดียวกับโฟลเดอร์กลยุทธ์ของมัน (`Strategies\Hedge\v1.0.1` ใช้ `Core\v1.0.1`) เมื่อมี Core มากกว่าหนึ่งรุ่น `--apply` ต้องระบุ `--target` เสมอ ไม่เช่นนั้นเครื่องมือปฏิเสธ
**รหัสออก:** 0 ตรงกันหมด, 1 พบความต่าง, 2 ผิดพลาด

## 4. verify_core — ตรวจสุขภาพ Core และกลยุทธ์
**คืออะไร:** ตรวจ 4 เรื่องในครั้งเดียว ไม่แก้ไฟล์ใดๆ (อ่านอย่างเดียว) จึงรันได้ทุกเมื่อ
1. **สำเนา Core:** ตรงกับต้นฉบับและตรงกับ `CORE_MANIFEST.txt` ไหม
2. **ธีม:** ค่าทุกตัวใน `CoreUI_Theme.mqh` เท่ากับธีมต้นฉบับ `docs\reference\HedgeUI_Theme.mqh` ไหม
3. **ไฟล์ .set:** Comment ขึ้นต้นด้วย `<TAG><Magic>`, ไม่เกิน 25 ตัวอักษร, Magic อยู่ในช่วงของ TAG, ไม่ซ้ำกัน
4. **EA และทะเบียน Magic:** `STRATEGY_TAG`, ลำดับ, `STRATEGY_MAGIC_BASE`, `STRATEGY_MAGIC_NEXT` ใน `<ชื่อ>_EA.mq5` ตรงกับ `MAGIC_REGISTRY.md` และไม่ล้าสมัย
**วิธีใช้:** ดับเบิลคลิก `tools\verify_core.bat` ดูบรรทัดสุดท้าย `สรุป: ERROR x | WARN y`
**ความหมายของข้อความที่เจอบ่อย:**
| ข้อความ | แปลว่า | ต้องทำ |
|---|---|---|
| `DIFF` / `MISSING` ที่สำเนา | สำเนาไม่ตรงต้นฉบับ | รัน `sync_core.bat` |
| `ถูกแก้หลัง sync (ไม่ตรง manifest)` | มีคนแก้ไฟล์ในสำเนา | ย้ายการแก้ไปที่ต้นฉบับ แล้ว sync ทับ |
| `ธีมขาด ...` / `ค่าไม่ตรง` | ค่าธีมต่างจากต้นฉบับ (ERROR) | คืนค่าธีมให้ตรงต้นฉบับ |
| `ธีมมีค่าที่ต้นฉบับไม่มี` | มีค่าคงที่เพิ่มในธีม (WARN) | ย้ายค่าคงที่ไปไว้ในไฟล์อื่น (เช่น Core_Panel.mqh ด้วย `#ifndef`) |
| `Comment ... TAG_MISMATCH / MAGIC_MISMATCH / COMMENT_TOO_LONG` | Comment ใน .set ผิดกติกา | แก้ `InpTradeComment` ใน .set |
| `Magic xxxxx ซ้ำ` | Magic ซ้ำในไฟล์ .set ต่างกัน | เปลี่ยนเลขตามทะเบียน |
| `STRATEGY_MAGIC_NEXT ล้าสมัย` | เลขถัดไปใน EA เก่ากว่าที่ใช้จริง | รัน `next_magic.bat --apply` แล้วคอมไพล์ |
**หลายรุ่นของ Core (D-28.1):** แต่ละสำเนาเทียบกับต้นฉบับรุ่นเดียวกับโฟลเดอร์กลยุทธ์ และตรวจว่า `core_version` ใน `CORE_MANIFEST.txt` ตรงกับรุ่นของโฟลเดอร์ ธีมตรวจทุกรุ่นของ Core
**ข้อควรรู้:** เครื่องมือหาไฟล์ EA ของกลยุทธ์จากชื่อ `<ชื่อกลยุทธ์>_EA.mq5` (เช่น `Hedge_EA.mq5`) ไม่ใช่ไฟล์ `_EN` หรือ `_TH`
**รหัสออก:** 0 ไม่มี ERROR, 1 มี ERROR, 2 เครื่องมือผิดพลาด

## 5. next_magic — บอกเลข Magic ถัดไป
**คืออะไร:** หา Magic ที่ใช้แล้วสูงสุดของแต่ละกลยุทธ์ จากทะเบียน `MAGIC_REGISTRY.md` และจากไฟล์ .set ทุกไฟล์ แล้วบวก 1 เป็น "Magic ถัดไปที่แนะนำ" ถ้าเกินช่วงของกลยุทธ์ (เช่น Hedge เกิน 19999) จะแจ้งปัญหา
**วิธีใช้:**
- ดับเบิลคลิก `tools\next_magic.bat` = **ดูอย่างเดียว** แสดงค่าใน EA ตอนนี้เทียบกับค่าที่ควรเป็น
- ให้แก้ค่าใน EA ให้ตรง: เปิด Command Prompt เข้าโฟลเดอร์ `tools` แล้วพิมพ์ `next_magic.bat --apply` เครื่องมือจะแก้บรรทัด `#define STRATEGY_MAGIC_NEXT` ในไฟล์ `<ชื่อ>_EA.mq5` ให้ **แล้วต้องคอมไพล์ EA ใหม่**
- เลือกเฉพาะกลยุทธ์: `next_magic.bat --strategy Hedge --apply`
**ข้อควรรู้:** ต้องลงทะเบียนเลข Magic ใหม่ในไฟล์ทะเบียนก่อนหรือสร้างไฟล์ .set ก่อน เครื่องมือจึงจะเห็นเลขนั้นว่า "ใช้แล้ว" เลข Magic ไม่นำกลับมาใช้ซ้ำ
**รหัสออก:** 0 ปกติ, 1 พบปัญหา, 2 ผิดพลาด

## 6. convert_sets — แปลง .set จากโปรเจกต์เก่า
**คืออะไร:** แปลงไฟล์ `SHORT_NN_*.set` ของโปรเจกต์อ้างอิงให้เป็นชุดของ Core ใหม่: ตั้ง `InpMagicNumber = ลำดับ EA x 10000 + NN`, ตั้ง `InpTradeComment = <TAG><Magic> S<NN>_<ชื่อย่อ>` (ไม่เกิน 25 ตัวอักษร), ตัดบรรทัด `InpStateImportLegacy` และ `InpTrailImportLegacy` ค่าอื่นไม่แตะ แปลงเฉพาะชื่อมาตรฐานชุด 01 ถึง 16 ตัวอื่นข้าม
**ใช้ตอนไหน:** ครั้งเดียวตอนนำ Preset จากโปรเจกต์เก่าเข้ามา ไม่ต้องใช้ในงานประจำวัน
**วิธีใช้:**
1. ดับเบิลคลิก `tools\convert_sets.bat`
2. ใส่ path โฟลเดอร์ .set ต้นฉบับ (ไม่ต้องมี `\` ท้าย path)
3. ดูตารางตัวอย่าง (ยังไม่เขียนไฟล์) แล้วกด `Y` เพื่อเขียนจริง
**ข้อควรรู้:** ไม่เขียนทับไฟล์ปลายทางที่มีอยู่แล้ว (ต้องใช้ `--force` ใน cmd) ปลายทางเริ่มต้นคือ `Strategies\Hedge\v1.0.0\Set` ใช้กับกลยุทธ์อื่นต้องระบุ `--dst`, `--tag`, `--ordinal`

## 7. compare_ref — เทียบฟังก์ชันกับโปรเจกต์อ้างอิง
**คืออะไร:** เทียบ "ทีละฟังก์ชัน" ระหว่างไฟล์ `Hedge1_*.mqh` ของโปรเจกต์เก่ากับโค้ด Core ใหม่ แล้วออกรายงาน
- `SAME` = เนื้อฟังก์ชันเท่ากัน (หลังแปลงชื่อที่ตกลงไว้ เช่น `HedgeStateGVName` → `CoreStateGVName`)
- `CHANGED` = มีส่วนต่าง ต้องให้คนตรวจดู diff ว่าเป็นการเปลี่ยนที่ตกลงไว้หรือไม่
- `MOVED/REMOVED` = ไม่พบชื่อที่แมปในโค้ดใหม่
- `NEW` = มีเฉพาะโค้ดใหม่
**ใช้ตอนไหน:** ตรวจข้อ C-09 ในชุดทดสอบ (พิสูจน์ว่า Core ใหม่ไม่ทำพฤติกรรมเปลี่ยนจากต้นฉบับ โดยไม่มีเหตุผล) เครื่องมือนี้ไม่ได้พิสูจน์ 100% ต้องให้คนตรวจฟังก์ชัน `CHANGED`
**วิธีใช้:** ดับเบิลคลิก `tools\compare_ref.bat` ใส่ path โฟลเดอร์ include ของโปรเจกต์อ้างอิง (ที่มี `Hedge1_*.mqh`) ผลรายงานเต็มอยู่ที่ `tools\out\compare_report.txt`
**ข้อควรรู้:** ฟังก์ชันที่เราเพิ่มหรือแก้ภายหลัง (เช่น Panel อัตโนมัติ, Lock Profit) จะขึ้น `CHANGED` หรือ `NEW` ตามที่ควร ให้บันทึกเป็น "การเปลี่ยนที่ตกลงไว้" (D-26)

## 8. Collector — เก็บ Log ตอนทดสอบ
**คืออะไร:** อ่านไฟล์ Log ของ MT5 (Experts และ Journal) แล้วแยกให้ทีละ Preset ตามเลข Magic พร้อมสรุปเป็นโฟลเดอร์ ส่งให้ผู้ตรวจได้ทันที ใช้ได้กับ EA ชื่ออะไรก็ได้ เพราะจับคู่ด้วยบรรทัด `Magic=<เลข>` ที่ EA พิมพ์ตอนเริ่ม
**ที่อยู่:** `tools\Collector_Tools\` โดยรันที่ `bots\Hedge1\run.bat` ตั้งค่าที่ `bots\Hedge1\collector_config.json` (ต้องมี `mt5_data_folder`, `preset_folder` ชี้ไป `Strategies\Hedge\v1.0.0\Set`)
**ขั้นตอนมาตรฐาน:**
1. ดับเบิลคลิก `run.bat` จะเห็นรายการ Preset พร้อมเลข Magic
2. พิมพ์หมายเลขที่ต้องการ (หลายชุด เช่น `2-7` หรือ `8,9,12,13` หรือ `all`) กด Enter ตรวจรายการ `Will collect:`
3. พิมพ์ `1` กด Enter (START) **ต้องทำก่อนแนบ EA**
4. แนบ EA บนกราฟ (แต่ละ Preset ต้องคนละ Timeframe) ทำการทดสอบ
5. จบแล้วรอ 10 วินาที (ให้ MT5 เขียน Log ลงไฟล์) กลับมาที่หน้าต่าง Collector
6. เมนูที่ใช้ได้: `1` ดูสถานะ | `2` Stop และ export ทุกชุด | `3` Stop และ export ทีละชุด | `4` จับคู่กราฟกับ Preset เอง | `0` ออกโดยไม่ export
**ผลลัพธ์:** `bots\Hedge1\output\<วันที่_เวลา>\<ชื่อชุด>_<Magic>\` ประกอบด้วย `Experts.session.txt`, `Journal.session.txt`, `Journal.ambiguous.txt` (บรรทัดที่ระบุ Magic ไม่ได้), `metadata.json` (รวม SHA-256 ของ .set และคำเตือน) และสำเนา .set ที่ใช้ ส่วนโฟลเดอร์ `raw` และ `unassigned` เก็บบรรทัดดิบและบรรทัดที่ยังไม่ระบุเจ้าของ
**ข้อควรรู้:**
- ถ้าตัว Collector บอก `No Magic key ... found` แปลว่าไฟล์ .set ไม่มี `InpMagicNumber`
- ข้อ A-15 และ A-16 (Init ล้มเหลว) ใช้ Collector ไม่ได้ เพราะ EA หยุดก่อนพิมพ์ Magic ให้คัดลอกบรรทัดจากแท็บ Experts แทน
- ตัวเลือกเสริม: ติดตั้ง `pip install MetaTrader5` เพื่อให้จับคู่หมายเลขไม้กับ Magic แม่นขึ้น (ไม่จำเป็น)
- รายละเอียดเต็มดู `tools\Collector_Tools\README.md` และ `Readme2.md`
- ถ้า Collector ออกจากโปรแกรมโดยไม่มี Error ไม่ได้แปลว่าการทดสอบผ่าน แปลว่าเก็บ Log ได้เท่านั้น ต้องตรวจไฟล์ที่ได้เอง

## 8.1 make_ai_bundle และ run_checks — ส่งงานให้ AI ที่เข้า GitHub ไม่ได้
**make_ai_bundle:** รวมเอกสารและโค้ดอ้างอิงเป็นไฟล์เดียวสำหรับแนบแชต ผลอยู่ที่ `ai_bundle\<วันที่_เวลา>\` ตัวเลือก: `--profile core`, `--add <path>`, `--redact <ข้อความ>`
**run_checks:** รัน sync_core (ตอบ N เสมอ ไม่คัดลอกอะไร), verify_core, next_magic แล้วรวมผลเป็น `tools\out\RUN_REPORT.txt` ตัวเลือก `--compile <ไฟล์.mq5> --metaeditor <path> --portable` ใช้คอมไพล์ผ่าน MetaEditor
ทั้งสองตัวไม่แก้ไฟล์โค้ดและไม่แตะ GitHub รายละเอียดเต็มดู `docs/handoff/OFFLINE_AI_WORKFLOW.md`

**check_docs:** ตรวจเลขมติซ้ำ/อ้างเลขที่ไม่มี, `D-26.x` เก่าที่ตกค้าง, ป้ายเตือนเอกสารเก่า, เอกสารเก่าหลุดเข้า Bundle และ path ที่เอกสารหลักอ้างถึง อ่านอย่างเดียว รันเองได้ด้วย `python tools\check_docs.py` และรันอัตโนมัติใน `run_checks` และ `make_ai_bundle` (ถ้าพบ ERROR `make_ai_bundle` จะหยุด ใช้ `--force` เพื่อข้าม)

**log_entry:** เขียนรายการต่อท้ายใน `docs/work/LOG_*.md` เติมเวลา เลขรายการ ไฟล์ที่แก้ ผลจาก RUN_REPORT และสถานะ Commit ให้ ใช้ `python tools\log_entry.py` (สร้างร่าง) แล้ว `--append` (ต่อท้ายหลังกรอกครบ) หรือ `--tail 10` (ดูรายการล่าสุด) ไม่แก้รายการเก่า ไม่ Commit

## 8.2 mock_edition_server — เซิร์ฟเวอร์จำลองสำหรับทดสอบ TradeDesk (T5)
**คืออะไร:** เซิร์ฟเวอร์ตรวจสิทธิ์จำลองตามสเปก `Strategies\TradeDesk\doc\SPEC_TradeDesk_EditionAPI_v0.1.md` ใช้ทดสอบไคลเอนต์ใน EA โดยไม่ต้องมีเซิร์ฟเวอร์จริง ใช้ไลบรารีมาตรฐานของ Python อย่างเดียว ใช้กุญแจทดสอบเท่านั้น (ห้ามใช้กับของจริง)
**วิธีใช้:** ดับเบิลคลิก `Strategies\TradeDesk\tools\mock_edition_server.bat` (หรือ `python Strategies\TradeDesk\tools\mock_edition_server.py`) ค่าเริ่มต้นฟังที่ `127.0.0.1` พอร์ต 80 เพราะ WebRequest ของ MT5 เลือกพอร์ตตามโปรโตคอล ถ้าพอร์ตถูกจำกัดให้เปิด Command Prompt แบบ Administrator แล้วเพิ่ม `http://127.0.0.1` (ไม่ใส่ path) ใน Tools > Options > Expert Advisors และตั้ง `TD_AUTH_URL` ใน `TradeDesk_AuthSecrets.mqh` ให้ตรง
**ควบคุมพฤติกรรม:** แก้ไฟล์ `Strategies\TradeDesk\tools\mock_edition_state.json` (อ่านใหม่ทุกคำขอ) ค่า `mode`: ok, badsig, badnonce, badid, stale, skew, expired, unknownedition, rate, down, badjson, slow ค่า `edition`: DEMO, TRIAL, STANDARD, PLUS, PRO หรือ AUTO (TRIAL ตามจำนวนวันที่ตั้ง แล้วเป็น STANDARD ข้อมูลวันที่เห็นครั้งแรกอยู่ใน `mock_edition_first_seen.json`)
**ข้อควรรู้:** ไฟล์สถานะทั้งสองถูกสร้างอัตโนมัติและอยู่ใน `.gitignore` | EA ต้องเป็น build ทดสอบ (`TD_EDITION_TEST`) จึงรับ URL แบบ http:// ได้ build แจกจริงรับเฉพาะ https:// | ผลทดสอบอยู่ใน `Strategies\TradeDesk\doc\CURRENT_STATE_TradeDesk.md` (T5 ชุด B)

## 9. สิ่งที่ tools ทั้งหมด **ไม่** ทำ
- ไม่คอมไพล์ EA (ต้องกด F7 ใน MetaEditor เอง)
- ไม่ทดสอบการเทรดหรือพิสูจน์ว่าโค้ดถูกต้อง (ตรวจเฉพาะความสอดคล้องของไฟล์และกติกา)
- ไม่ Commit หรือแตะ GitHub
- ไม่ลบไฟล์ใดๆ (sync_core สำรองก่อนทับ และไม่ลบ `EXTRA`)
